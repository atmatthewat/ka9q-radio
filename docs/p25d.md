Decoding P25 with ka9q-radio
Matthew Kaufman, KA6SQG, November 2026
=====================================

*p25d* decodes APCO Project 25 (P25) Phase 1 signals from *radiod*. Like *pcmrecord* and *monitor*, it listens to a multicast group and handles every channel (SSRC) on it at once, so one *radiod* instance and one *p25d* can follow a trunked system's control channel and all of its voice channels. Each channel gets its own receiver thread.

*p25d* is new. Today it follows Phase 1 control and voice channels (C4FM and the simulcast modulations, with no setting to choose between them), decodes and logs every trunking message, and reports voice, header and terminator data units as they arrive. It does not yet produce audio, follow calls from a control channel to its voice channels, or decode Phase 2.

## Configuring *radiod*

*p25d* needs complex baseband (I/Q), not demodulated audio, at 19.2 kHz: four samples per 4800 baud symbol. Add channels like these to your *radiod* config (see **config/examples/fragments/p25.conf**):
```
[P25]
data = p25-iq.local
mode = iq
samprate = 19200
low = -5k
high = +5k
encoding = f32le
agc = no
gain = 60
freq = "851m0125 851m2625 851m5125"
```
Each frequency becomes a separate channel with its own SSRC, all sent to **p25-iq.local**. With the default 20 ms block time, 19.2 kHz is 384 samples per block.

The *iq* preset turns on the linear demodulator's AGC, which scales I and Q together. *p25d* sets its own level, so turn the AGC off and use a fixed gain. With 32-bit floats (**f32le**) there's no clipping, so the gain only has to be roughly right. 16-bit integers (**s16be**, half the network traffic) also work: either keep 30 dB or more of margin with a fixed gain, as the WSPR example does, or leave the AGC on with **hang-time = 0** as the HFDL example does. *p25d* accepts **s16be**, **s16le**, **f32le** and **f32be**; it ignores mono and Opus streams.

## Running *p25d*

```
p25d [options] p25-iq.local [more groups ...]
```
- **-I**, **--input** *group*: add an input group (groups may also be given without -I)
- **-v**, **--verbose**: more messages; repeat for more detail. At -v each channel also logs a status line
- **-u**, **--update** *seconds*: interval between the -v status lines (default 10)
- **-t**, **--timeout** *seconds*: close a channel after this long without data (default 20)
- **-S**, **--ssrc** *ssrc*: decode only this channel
- **-o**, **--source** *name-or-address*: accept only this sender (source-specific multicast)
- **-A**, **--iface** *interface*: default multicast interface
- **-l**, **--locale** *locale*: locale for number formatting (default $LANG)
- **-V**, **--version**: show version and exit

*p25d* learns each channel's sample rate, encoding and frequency from the status *radiod* sends alongside the data, so a channel starts a second or so after *p25d* (or *radiod*) does. Lost packets are replaced with zeroes so the symbol timing holds; late and reordered packets are put back in order; gaps longer than a second are skipped.

## Output

Decoded events go to standard output, one line each, and everything else (errors, startup messages) to standard error. Every event line starts with the time of the signal (from *radiod*'s clock, in the same format *packetd* uses), the SSRC and the channel frequency:
```
Sun 22 Nov 2026 08:14:05.443000 UTC ssrc 851012 851.012500 MHz NAC 443 TSBK NET_STS_BCST lra=0x00 wacn=0xbee00 sys=0x445 ch=0-1117 class=0x70
Sun 22 Nov 2026 08:14:05.503000 UTC ssrc 851012 851.012500 MHz NAC 443 TSBK GRP_V_CH_GRANT_UPDT tg=11027 ch=3-1264 tg_b=11327 ch_b=3-1355
Sun 22 Nov 2026 08:14:05.643000 UTC ssrc 851012 851.012500 MHz NAC 443 TSBK IDEN_UP_TDMA iden=2 type=3 tdma=1 slots=2 base=851.012500 spacing=12500 bw=12500 tx_offset=-45000000
```
Trunking messages are always logged, decoded: the message name as in TIA-102.AABC, then its fields. Talkgroups and radio IDs are decimal; NAC, WACN and system ID are hex. A channel prints as *identifier-number*, with its frequency in MHz (and TDMA slot) once the site has broadcast that identifier.

With **-v**, voice, header and terminator data units are logged as they arrive, and each channel logs a status line every **--update** seconds:
```
Sun 22 Nov 2026 08:15:17.129999 UTC ssrc 851012 851.012500 MHz status: locked, offset +32.9 Hz, syncs 797 weak 2, TSBK 2,335 bad 61, LDU 0, 19,200 Hz, packets 6,000 drops 0 dupes 0 filled 0 resyncs 0 overruns 0
```
It shows whether frame sync is held, the estimated carrier offset from the channel frequency, frame syncs found (and those accepted on a weak match because the NAC agreed), trunking blocks that passed and failed their CRC, voice data units, and the stream counters: packets received, lost, duplicated, zero samples filled in for lost packets, gaps too long to fill, and blocks dropped because the decoder fell behind. With **-vv**, blocks that failed their CRC are logged too.

## Running as a service

```
sudo systemctl enable --now p25d@p25-iq.local
tail -f /var/log/p25d.log
```
The instance name is the multicast group. All instances append to **/var/log/p25d.log**; standard error goes to the journal (**journalctl -u p25d@p25-iq.local**).
