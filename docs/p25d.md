Decoding P25 with ka9q-radio
Matthew Kaufman, KA6SQG, November 2026
=====================================

*p25d* decodes APCO Project 25 (P25) Phase 1 signals from *radiod*. Like *pcmrecord* and *monitor*, it listens to a multicast group and handles every channel (SSRC) on it at once, each in its own receiver thread. It:

- decodes and logs every trunking message, header, link control word, encryption sync and packet data unit;
- follows trunked calls: when a control channel grants a voice channel, *p25d* asks *radiod* for that channel, decodes it, and lets it go when the call ends;
- sends the speech of clear (unencrypted) calls as ka9q-radio RTP audio streams that *monitor* plays and *pcmrecord* records.

Phase 2 (TDMA) voice is not decoded yet: Phase 2 grants are logged and not followed.

The receive filter is chosen automatically for each channel from its signal (sharp for constant-envelope C4FM, gentle for linear simulcast) and needs no setting.

## Configuring *radiod*

*p25d* needs complex baseband (I/Q), not demodulated audio, at 19.2 kHz: four samples per 4800 baud symbol. For a trunked system, configure only the control channel(s); *p25d* asks for the voice channels itself. For a conventional channel, configure it the same way. See **config/examples/fragments/p25.conf**:
```
[P25]
data = p25-iq.local
mode = iq
samprate = 19200
low = -5k
high = +5k
encoding = f32le
agc = no
gain = 60
freq = "857m98125"
```
Each frequency becomes a separate channel with its own SSRC, all sent to **p25-iq.local**. With the default 20 ms block time, 19.2 kHz is 384 samples per block.

The *iq* preset turns on the linear demodulator's AGC, which scales I and Q together. *p25d* sets its own level, so turn the AGC off and use a fixed gain. With 32-bit floats (**f32le**) there's no clipping, so the gain only has to be roughly right. 16-bit integers (**s16be**, half the network traffic) also work: either keep 30 dB or more of margin with a fixed gain, as the WSPR example does, or leave the AGC on with **hang-time = 0** as the HFDL example does. *p25d* accepts **s16be**, **s16le**, **f32le** and **f32be**; it ignores mono and Opus streams.

### Voice channels created on demand

A voice channel *p25d* asks for is made in the control channel's form: the same sample rate, encoding, filter, gain and AGC setting, and the same data group. Set these on the control channel as above. Three things come from elsewhere:

- *radiod* builds a new channel from its **[global]** section, and two of its settings can't be changed by a request. **data =** must be set in [global] (without it *radiod* can't create channels at all); using the control channel's group there is simplest. **ttl =** in [global] is the new channels' multicast TTL: **ttl = 0** keeps them on the *radiod* host, so a *p25d* on another machine would see the control channel (if its own section says **ttl = 1**) but none of the voice channels.
- The front end must cover the voice frequencies. *p25d* never asks for a channel outside the front end's tuning range, because *radiod* would retune the front end and move every other channel, the control channel included. It logs such a frequency once and doesn't ask again.
- *p25d* sends its requests to the *radiod* that sent the control channel; it learns the command address from the channel's status, so there is nothing to configure. Commands go out with TTL 1, as *tune* and *control* send them.

A requested channel goes away by itself a few seconds after *p25d* stops asking for it, so one left behind by a crash doesn't stay. When a call ends, or *p25d* exits, its channels are released at once.

## Running *p25d*

```
p25d [options] p25-iq.local [more groups ...]
```
- **-I**, **--input** *group*: add an input group (groups may also be given without -I)
- **-R**, **--pcm-out** *group*: send voice to this multicast group (e.g. **p25-pcm.local**); without it, no audio
- **-N**, **--name** *name*: name the voice output is advertised under (default p25d)
- **-T**, **--ttl** *ttl*: multicast TTL of the voice output (default 0: this host only)
- **-p**, **--tos** *tos*: IP type of service of the voice output (default 184, expedited forwarding)
- **-n**, **--no-follow**: don't follow calls; only decode the channels already there
- **-g**, **--talkgroups** *list*: follow group calls on only these talkgroups, e.g. **2501,2600-2699** (repeatable)
- **-x**, **--exclude** *list*: never follow these talkgroups (repeatable)
- **-m**, **--max-calls** *n*: follow at most *n* calls at once (default: no limit)
- **-e**, **--encrypted**: follow encrypted calls too. They are logged; their voice is never decoded
- **-v**, **--verbose**: more messages; repeat for more detail. At -v each channel also logs a status line
- **-u**, **--update** *seconds*: interval between the -v status lines (default 10)
- **-t**, **--timeout** *seconds*: close a channel after this long without data (default 20)
- **-S**, **--ssrc** *ssrc*: decode only this channel (turns call following off)
- **-o**, **--source** *name-or-address*: accept only this sender (source-specific multicast)
- **-A**, **--iface** *interface*: default multicast interface
- **-l**, **--locale** *locale*: locale for number formatting (default $LANG)
- **-V**, **--version**: show version and exit

*p25d* learns each channel's sample rate, encoding and frequency from the status *radiod* sends alongside the data, so a channel starts a second or so after *p25d* (or *radiod*) does. Lost packets are replaced with zeroes so the symbol timing holds; late and reordered packets are put back in order; gaps longer than a second are skipped.

## Following calls

Any channel on which trunking blocks decode is a control channel. *p25d* keeps track of its calls: grants and grant updates, the voice channels' link control, headers and terminators, and the site's patches. For each call it decides whether to follow it, and logs it either way.

A followed call's channel is requested from *radiod* when the grant comes, asked for again as grant updates come and kept alive while its voice arrives. It is released when a terminator ends the call, when the channel is granted to another call, or 3 seconds after the last voice and the last grant. The voice channel's receiver starts with the control channel's carrier offset, since both come from the same site.

Calls not followed: encrypted calls (unless **-e**); talkgroups outside **-g** or inside **-x**; calls beyond **-m**; Phase 2 (TDMA) calls, for which there is no receiver yet; and calls on frequencies outside the front end.

Channels configured in *radiod* that no grant names (a conventional P25 channel, say) are decoded as before, with audio under the same rule as everything else.

## Voice output

With **-R**, the speech of clear calls is decoded with the IMBE vocoder and sent as 8 kHz mono 16-bit audio, one RTP packet per 20 ms, with status packets as *radiod* sends them, so *monitor* plays it and *pcmrecord* records it. RTP timestamps are *radiod*'s clock, so a recording lines up with the I/Q it came from.

**No speech is ever sent from an encrypted voice unit, or from one not yet known to be clear.** A voice unit is decoded only after a header or encryption sync of the same transmission, passing its error correction, has said it is unencrypted (algorithm 0x80), and only while nothing has said otherwise (another algorithm, link control that is protected or carries the encrypted service option). On a trunked channel the call tracking must also have labelled it clear. Voice units that arrive before that (on late entry into a call, for instance) are held, at most a second and a half of them, then decoded in order with their original timestamps once confirmed clear, or dropped if the call turns out encrypted or ends first.

Streams:

- A trunked group call's stream has the **talkgroup number as its SSRC**, whichever voice frequency carries it, so a listener sees one stream per talkgroup. Talkgroup numbers are unique only within one system: if one *p25d* (or several sharing an output group) follows more than one system, two systems using the same talkgroup number would send on the same SSRC. For now, run one *p25d* with its own output group per system. A way to tell systems apart (an SSRC base per system, a map file, or one output group per system) may be added later.
- A unit-to-unit or telephone call, and any channel without call tracking, uses the voice channel's own SSRC.
- The status carries the voice frequency and a description such as **P25 TG 2501 src 1118028 "ENGINE 5" NAC 443**: talkgroup (or unit), source, the talker alias when one has been received, and the system's NAC. *pcmrecord* puts the description in its log and file attributes; *monitor* shows the frequency.

### The vocoder

IMBE decoding uses mbelib (https://github.com/szechyjs/mbelib), which is optional. If its header **mbelib.h** is found when *p25d* is built, it is used; otherwise *p25d* is built without a vocoder, says so once when it starts, and does everything else. mbelib's own README says it is for educational purposes only and that the algorithms may be covered by patents, so packagers may prefer to build without it. Its speech level is left as mbelib produces it.

## Output

Decoded events go to standard output, one line each, and everything else (errors, startup messages) to standard error. Every event line starts with the time of the signal (from *radiod*'s clock, in the same format *packetd* uses), the SSRC and the channel frequency:
```
Sun 22 Nov 2026 08:14:05.443000 UTC ssrc 857981 857.981250 MHz NAC 443 TSBK NET_STS_BCST lra=0x00 wacn=0xbee00 sys=0x445 ch=0-1117 class=0x70
Sun 22 Nov 2026 08:14:05.503000 UTC ssrc 857981 857.981250 MHz NAC 443 TSBK GRP_V_CH_GRANT tg=2501 src=1118028 svc=0x04 prio=4 ch=0-1597 freq=860.987500
Sun 22 Nov 2026 08:14:05.643000 UTC ssrc 857981 857.981250 MHz NAC 443 TSBK IDEN_UP_TDMA iden=2 type=3 tdma=1 slots=2 base=851.012500 spacing=12500 bw=12500 tx_offset=-45000000
```
Trunking messages are always logged, decoded: the message name as in TIA-102.AABC, then its fields. Talkgroups and radio IDs are decimal; NAC, WACN and system ID are hex. A channel prints as *identifier-number*, with its frequency in MHz (and TDMA slot) once the site has broadcast that identifier.

Each call gets one line when it starts and, if followed, one when it ends, on the control channel. They show the talkgroup (or unit), source, talker alias once known, voice frequency, the voice channel's SSRC and flags (emergency, encrypted, patched); a call not followed says why; the end gives the duration, voice units, link control and encryption sync words that failed, bits corrected in the voice frames, and why the call ended (terminator, timeout, new call on the channel, the channel's link control naming another call, control channel lost, shutdown):
```
Sun 22 Nov 2026 09:52:43.509 UTC ssrc 857981 857.981250 MHz NAC 443 call start group tg 2501 src 1118028 voice 860.987500 MHz ssrc 860988
Sun 22 Nov 2026 09:53:15.149 UTC ssrc 857981 857.981250 MHz NAC 443 call end group tg 2501 src 1118028 voice 860.987500 MHz ssrc 860988 after 31.7 s, 156 voice units, 1 words bad, 413 bits corrected, timeout
Sun 22 Nov 2026 09:52:12.370 UTC ssrc 857981 857.981250 MHz NAC 443 call start group tg 11057 src 0 voice 769.906250 MHz slot 1, not followed: Phase 2 (TDMA), no receiver for it yet
Sun 22 Nov 2026 09:52:45.805 UTC ssrc 857981 857.981250 MHz NAC 443 can't follow calls on 857.187500 MHz (ssrc 857188): outside the front end's coverage; not asking for it again
```
(The times here are shortened.) With **-v** the end of calls not followed is logged too, and site, patch and control channel changes; with **-vv**, every call update.

With **-v**, voice, header and terminator data units are logged as they arrive (a terminator with link control gives two lines: the link control, then the terminator), and each channel logs a status line every **--update** seconds:
```
Sun 22 Nov 2026 08:15:17.129999 UTC ssrc 857981 857.981250 MHz status: locked, offset +32.9 Hz, filter gentle, syncs 797 weak 2, TSBK 2,335 bad 61, LDU 0, words bad 0, 19,200 Hz, packets 6,000 drops 0 dupes 0 filled 0 resyncs 0 overruns 0
```
It shows whether frame sync is held, the estimated carrier offset from the channel frequency, the receive filter in use, frame syncs found (and those accepted on a weak match because the NAC agreed), trunking blocks that passed and failed their CRC, voice data units, header, link control and encryption sync words that failed to decode, and the stream counters: packets received, lost, duplicated, zero samples filled in for lost packets, gaps too long to fill, and blocks dropped because the decoder fell behind. The thousands separators appear only under a locale that groups digits (**-l**, or $LANG). With **-vv**, blocks that failed their CRC are logged too.

## Running as a service

```
sudo systemctl enable --now p25d@p25-iq.local
tail -f /var/log/p25d.log
```
The instance name is the multicast group. All instances append to **/var/log/p25d.log**; standard error goes to the journal (**journalctl -u p25d@p25-iq.local**). For voice output or other options, override **ExecStart** with **systemctl edit p25d@p25-iq.local**, e.g. **ExecStart=/usr/local/sbin/p25d -R p25-pcm.local %i** (after an empty **ExecStart=** line).
